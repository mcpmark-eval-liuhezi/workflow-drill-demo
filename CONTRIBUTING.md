# Contributing Guide

Thanks for wanting to contribute! This guide covers the basics of how we work together.

## How to contribute

- **Open an issue** First, describe your idea or bug in an issue so the team can discuss it before any code is written.
- **Branch from `main`** Create a new branch with a descriptive name (e.g., `add-contributing-guide`) off `main`.
- **Make your change** Keep commits small and focused. One logical change per commit.
- **Open a pull request** Link the relevant issue in the PR description and explain what your change does.
- **Request a review** Ask at least one team member to review your pull request before merging.
- **Address feedback** Respond to reviews politely and push follow-up commits to the same branch.
- **Merge** Once approved and tests pass, a maintainer merges your pull request into `main`.

## Coding conventions

- Follow the existing style in the codebase.
- Keep pull requests under ~400 lines of Diff where possible.
- Update the README if your change changes how the project is used.

## Questions?

If anything is unclear, open an issue and ask on the pull request — we'd rather answer early than guess late.
